# A change to drawing on the stream

Drawing on the stream is ADR 0013's, built in parts: M27a the board between stream windows (`docs/m27a-results.md`), M27b the host's board over the game (`docs/m27b-results.md`), M27c text boxes (`docs/m27c-results.md`), M27d the host's own stream window (`docs/m27d-results.md`), M27e pictures (`docs/m27e-results.md`). The wire is `docs/protocol.md`'s "Drawing on the stream"; CLAUDE.md's Sessions rules ("Drawing on the stream", "The host's board over the game") are the law.

## The two editors stay alike

The stream window's editor is egui in Rust, the board overlay's is TypeScript: two copies, held together three ways.
- **One rules file.** `boardRules.ts` is written by `cargo test -p couch-engine` (`couch_engine::board::rules_ts`, test `the_board_rules_are_written_for_the_front_end`) from `couch_proto::board` and `couch_input::shortcuts`. Never hard-code a limit, colour, width, timing or key in the front end: add it to the Rust table, to `rules_ts`, and run the test. A new `DrawAction` or `DrawTool` needs a line in `rules_ts`'s `action_ts` and `tool_name`.
- **One set of cases.** Every case in `editor/tests.rs` has its twin in `editor.test.ts`, same name in words, same steps, same numbers. A change to one editor's behaviour changes both editors and both case files in the same PR; a new behaviour gets a case in both.
- **The same painting.** `paint.ts` follows `draw_ui.rs`'s `element_shapes`: the same widths (`line_width`), see-through highlighter (0.38), arrow heads, laser trail (two strokes, a white head), ping (a ring pulsing twice in its time, the name below). Compare `preview.html?board` (shot `board-drawing`) with the stream window's `drawing` HUD state (`viewer-shots.ps1`). Text (M27c) follows `paint_text`: each line from the box's first point, `LINE_HEIGHT` ems apart, top-aligned, over a black shadow at 0.6 offset by 6% of an em; the box being typed in as a thin blue frame, the caret and an input method's underlined composition (shots `board-typing`, and the stream window's `typing` state).
- **One measure each, one in the cases.** A text box's second corner is measured by its author's font (`Measure`: egui's in `draw_ui.rs`, set at the first paint since egui's fonts exist only then; `canvasMeasure` in `paint.ts`); the shared cases use the default estimate (half an em a character) on both sides, and compare corners within one unit (Rust rounds `f32`, TypeScript `f64`). Text is counted in Unicode scalar values on both sides (`chars()`, `Array.from`), never UTF-16 units; `cleanText` and `validText` are ports of `couch_proto::board`'s, checked by the same cases.

Port by translation, not by rewrite: keep the function names (`press`, `drag`, `release`, `take_batch` → `takeBatch`), their order and their comments, so a diff of one shows where the other changes.

## Rules that are easy to break

- **Only the author's own:** elements are keyed by the connection's member (or the host's `set_me` id), never by a member named in a message. Editors select, erase, move and undo only `me`'s.
- **Generations:** a batch carries the generation it was made in (the outbox's, not the latest); a clear of ours or everyone's, and every snapshot, starts a new one; a stale batch is dropped unsaid. After a clear of ours (a snapshot among them) an editor calls `cleared`, then `finishStrays`; after any other news, `sync`.
- **Batches are taken whole or refused,** and refusals must never make the host resend a member's drawing over and over (`resync_due`, at most once a second).
- **The keyboard seat's holder draws nothing,** nor the host while desktop control lasts; drawing input never enters the input path (the stream window's `InputCapture::set_drawing`; the board page's keys never leave it).
- **The host's board over the game** is the M8 overlay rule's one exception: only the host's own key at the PC begins drawing mode; never a command, the webview or a device. Keep every end in place (the key, Esc or Done, the focus going once the board had it, the board unable to show, the panic key, drawing off, the stream stopping, desktop control, the end).
- **The host's two windows are one author** (M27d): the board over the game and the host's own stream window both draw as the host. A taken batch of the host's comes back from the session as `Effect::HostDrew`, which `host_drew` sends only to the window that didn't draw it (back to its own, a stroke's appended points would double); whatever the session tells the host (`Effect::HostBoard`) goes to both (`to_host_windows`), so a snapshot asked by either puts both in the same generation. Both editors bump their next id past what they hear (`sync`), so ids made in one don't collide with the other's, except for batches from both within the echo's moment (one mouse makes it unlikely; the M27d review's kept finding). A refusal goes to the window that drew alone; the own window gets the board as it opens in the generation as it is (`HostSession::host_snapshot`), so the other's batch on its way still counts. The own window has no seat and no input path: only its drawing, keyframe asks, its state and its closing are read.
- **Typing has every key** (M27c): while a text box is typed in, the stream window routes keys to `text_key` and text to `type_text` (SDL's text input on only then), the board page lets characters into its hidden field and nothing reaches a drawing key; Esc finishes the box before it leaves anything. Points are a stroke's alone: the host refuses `Append` on a text box, so whatever finishes one (`finish_strays`, `finish_open`) sends the box again with `done`. Its editing is a text field's (a selection `mark` beside the caret, word moves by `class`/`charClass`, kept alike in both editors); the TypeScript `textKey` takes Shift and Ctrl last (`shift`, `word`), the Rust one before the board.
- **The toolbar's hiding is the window's** (`DrawAction::ToggleToolbar`, Tab; `Keyed::ToggleToolbar` from the editor, which changes nothing of its own): the stream window's `Drawing::tools_hidden` and the page's `toolsHidden`. Hidden, the pill is all the toolbar's area (`Drawing::toolbar`, which the HUD hit-tests); shown, that area includes the handle above it.
- **A wire change** (a new op, element kind, message or field) is a new wire revision: the `protocol-change` skill.
- **Pictures go only by their upload** (M27e): an editor's `emit` queues a `Put` of a picture as an upload (`Out::Picture`) whenever the board doesn't show that id with that hash yet (a paste, a copy, an undo of an erase, a redo), and `take_batch` stops before it, so it goes after what came before; the host refuses a batch's `Put` that would bring one in. Bytes are the window's, kept by id; a window sends an upload only with them. The engines hold a window's later batches until its picture is answered (`Gate`): never send a batch around it.

## Pitfalls already met

- **A picture's bytes sent once per viewer** (M27e): `pictures_sent` must be pruned of pictures gone from the board **before** an upload is taken, or a picture erased and put back counts as sent (the session test caught it).
- **A new generation reaches a window before anything that lets it draw** (P17): turning drawing on sent `BoardState` before the snapshot of the new generation, so a window (or a test) drawing as soon as it heard "on" drew in the old one and the host dropped it as stale, unsaid: the picture scenario failed once in six under load, and the own window's the same way after drawing off. `set_drawing` now sends the board (or the clear) first. So does a newcomer's `board_for` (the snapshot, then `BoardState`). In the session scenarios, wait for the window's generation to change before drawing after anything that starts one.
- **Answers by upload number, never by element id** (P17): a late `PictureAnswer` for an upload given up on (75 s) could open the gate of a newer upload of the same element. `PictureUpload.upload` comes from one count for the whole process (`NEXT_UPLOAD`), never restarting with a connection, a watch or a window; the host's own windows' gates number theirs the same way.
- **The host asks before it reads** (P17): `couch_net::pictures::read_upload_header`, then `Input::PictureComing` to `HostSession::picture_coming` (the board's `admit`, the cheap checks `take` runs too, without spending the rate), then `UploadBytes::read` or `refuse`. Keep the cheap checks in `admit` alone, so the two can't drift. Every upload counts toward the rate once: refused at its header, there; let through, at its take; bytes that weren't a picture, by `count_refused`. Bytes that don't come whole are answered as no picture, never left unanswered.
- **The TypeScript `DrawAction` is an object** (`{ type: "undo" }`), not a string, in the shared cases.

- **A swallowed shortcut key across drawing mode** (M27a review): the window swallows a shortcut's key so its release stays in the window; in drawing mode that release went to the board, and the key later stuck down on the host. Entering or leaving drawing mode forgets every swallowed key and button.
- **Sharing in TypeScript where Rust clones:** an op queued in the outbox and the element on the board must be separate objects (`cloneElement`, `copyOp`), or `merge` growing an outbox stroke also grows the shown one twice. Tests that replay sent ops must replay copies (`hostsCopy`).
- **Rust's `signum(0.0)` is 1, `Math.sign(0)` is 0:** a square or circle dragged straight down or across needs `dx < 0 ? -1 : 1`.
- **`WindowFromPoint` and click-through windows:** it sees through a window with both `WS_EX_TRANSPARENT` and `WS_EX_LAYERED` (measured in M27b), so the board over the game leaves `pointer_over` finding the game. A first test seemed to say otherwise: WinForms had dropped the style when its opacity was set. Check a window's real style before believing a probe.
- **tao's setters show the window** (`ShowWindow`): the engine changes the board's styles itself (`SetWindowLongPtr`) and places it with `SetWindowPos` and `SWP_ASYNCWINDOWPOS` (a move posted, never waiting on the app's UI thread); changing a style still waits on it, so only at drawing's start and end.
- **One webview data folder, one set of environment options** (the author's one-PC run of M27b): the board window shares the main window's data folder, and WebView2 refuses a second webview there unless its environment options match (the main window sets `scrollBarStyle: fluentOverlay`). `src-tauri`'s `BoardWindow::open` copies them from the main window's configuration; keep it so for any new one. And a window that can't be made is tried once, never on every change (each try flashed a window): `BoardOverlay::failed`.
- **A new webview is white until its page loads:** the board shows and takes the focus only after its page has said so (`HostBoard`), and that word can reach the engine before the engine hears the window was made: it counts while the window is opening.
- **Cached answers end things:** the follower kept the exclusive-full-screen answer 500 ms, and a drawing begun just after a game left full screen ended at once. While drawing it asks every tick.
- **The focus grace counts from the focus given,** not from the key: opening a window and loading its page can take longer than the grace.
- **A board window can go** (Alt+F4, a webview crash): the follower reports it gone and the engine opens another; the app refuses closing it any other way, and closes only the window it made (by handle, never by label).
- **Text kept even when empty** in the console uses a no-break space: an edit's old text must hold it too.
- **The board page's clipboard comes through the page's own `copy` and `paste` events,** which carry the system clipboard without a permission: the key handler must not `preventDefault` Ctrl+C and Ctrl+V, or they never fire. Its hidden field holds the focus through drawing mode (a toolbar click gives it back), so the events and an input method's text arrive.
- **Text moves go by character, not by what reads as one letter** (M27c): a decomposed "é" or a joined emoji can be split by Left, Right or Backspace, in both editors alike; a line break is a kind of its own for word moves (`BREAK`), never part of a word or a double click's selection.
- **Vitest needs the drive letter upper-case:** run from `C:\dev\...` (`cd /C/dev/...` in Git Bash); from a lower-case `c:` working directory every test file fails to load ("no tests").
